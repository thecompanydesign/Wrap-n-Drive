Colour proposal — for review before implementation

Dark mode
for Wrap&Drive.

The build spec never defined a dark palette, so this extends its own logic rather than inventing a new one: same near-monochrome restraint, same single red accent, same hairline rules — just re-tuned for a dark ground. Nothing here is a mechanical invert; every token was re-picked so it still does its original job — heading, label, rule, ghost — at the right weight against black instead of white.

The accent doesn't move

#e8261c stays identical in both themes. It's the one deliberate colour in an otherwise monochrome system — changing it per theme would make the logo feel like two different brands.

The black card flips polarity

The pricing page's "black card" is only black because it's the one surface that must pop against a white page. On a dark page that same job needs a light fill — so in dark mode it becomes the white card. Same signature detail, same intent, inverted fill.

Same token names, new values

Every component already reads colour from a CSS custom property (var(--ink), var(--rule)…). Dark mode is a second value for each token, swapped by a [data-theme] attribute — no component styles change.
